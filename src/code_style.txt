**Coding Style for the Source Code**

1. We follow the libgretl coding style, including its indentation conventions.

2. We use `nullptr` instead of `NULL` for pointers.

3. We consistently qualify standard library types and functions with the `std::` namespace (e.g., `std::string` and `std::free()`).

4. Private class member names are suffixed with `_`.

5. We prefer RAII (Resource Acquisition Is Initialization) and smart pointers over manual resource management. Resources acquired from libgretl should be managed using appropriate deleters.

6. We make ownership semantics explicit. Borrowed pointers must not be freed, and ownership transfers should be performed deliberately, using `release()` only when ownership has been successfully transferred.

7. We strive for exception-safe code. Resources must be released correctly even when an operation fails or throws an exception.

8. We use `const` wherever appropriate to express immutability and prevent unintended modifications.

9. We prefer anonymous namespaces over `static` functions for translation-unit-local helpers.
