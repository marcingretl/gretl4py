# priority28 — ARprobit and staticfactor (source-reviewed)

Eight plotting fixtures for two contributed packages not covered by earlier
custom batches. Both are grounded in the archived upstream `.gfn` and bundled
`.gdt` files. **They have not been run against the user's gretl4py runtime.**

## Packages and sources

- `audit/contributed/ARprobit.zip` — `ARprobit` v0.8 (2026-01-31,
  Sven Schreiber); original `cycles_and_spread.gdt` data and its sample script.
  The sample estimates `ARprobit(y, explain, 1, TRUE)` and explicitly plots
  `dp.yhat` with recession shading using `gnuplot ... --band=recshades`.
  The source also includes a gappy `{2, 2}` lag example. The package itself
  does **not** provide a plotting function; these four cases adapt its
  *actual sample* and plot the fitted probabilities from the public estimator.
- `audit/contributed/staticfactor.zip` — `staticfactor` v0.82 (2023-03-13,
  Riccardo "Jack" Lucchetti and Sven Schreiber); original `bg2.gdt` data.
  Cases call the exported `staticfactor()` and the package-native `SF_plot()`
  (bundle plot), using models and estimation methods in the source sample.

We postponed `cointARDL`: its only plotted example is a synthetic simulation
outside the public `setMod()`/`runCoint()` routines, and the package depends
on `ADMBP` and `SB`. Four plotting tests would not provide comparable package
coverage. `gregory_hansen` remains another viable future candidate.

## Implementation notes

- `ARprobit` cases deliberately retain `open ... --frompkg=ARprobit`, the
  original quarterly sample period 1955:4–2005:4, `spread=tcm10y-tbsm3m`,
  and the recession overlay `bundle recshades=_(dummy="y")`. They differ only
  in documented inputs to the real estimator. Their plotting code follows
  the original sample script; no native plot API exists in this package.
- `staticfactor` `SF_plot(&fit)` is a `bundleref` function and emits its own
  Gnuplot script via `plot ... end plot --output="display"`. The native plot
  uses linepoints on eigenvalue/rank data. There is only one supported
  scree plot type, so we vary the actual estimation method and covariance
  input rather than inventing unsupported plot modes.
- Case 06 rescales `bg2cost1` by a factor of two before covariance PCA.
  The original `bg2.gdt` variables are already standardized to variance one;
  without this transformation covariance and correlation PCA produce
  indistinguishable scree plots, reducing the value of the regression test.
  The data remain the original observed package dataset, and the scree plot
  is still generated by the package's own `SF_plot()` function.
- Both data files must be installed alongside their respective `.gfn` files;
  the source ZIPs contain them. If a test raises `FileNotFoundError`, check
  the installed package resources before attributing it to gptranslate.
- Case 08 uses the upstream sample's maximum-likelihood estimator and may
  expose numerical/convergence differences in the test environment. Do not
  replace the estimator with an artificial plot to force a PASS.
- A `PASS` means the Python/Matplotlib execution produced an active figure.
  It does **not** guarantee correct labels, x-axis conventions, recession
  shading or spectral shapes; inspect all PNGs before committing.

## Running the cases

From `gretl-gretl4py/tests/plots`:

```bash
python probe_package_batch.py --custom priority28 \
    --cases 01_ARprobit_sample_AR 05_SF_PCA_correlation \
    --approved --continue-on-error

python probe_package_batch.py --custom priority28 \
    --approved --continue-on-error
```

The `preload/` scripts provide a time-series dataset for loading the
function package; the sample scripts replace it with the original packaged
`.gdt` file. Review `logs/` and `images/` before finalizing this batch.
